# F0-18 — matrix runner report (fix 2)

## What changed

The runner no longer needs the key-minting service or a master key. Keys are
minted in one batch by the owner on the gateway host and handed out from a file;
the task set comes from the public manifest.

- `factory/run_matrix.py`
  - `KeyPool` implements the existing `KeyClient` protocol:
    - `--keys-file PATH` (default `$FACTORY_KEYS_FILE`) is one virtual key per
      line. The file must be mode 600 or stricter; `KeyPool` refuses anything with
      group/other bits. When present it replaces `FACTORY_KEYS_URL` /
      `FACTORY_KEYS_TOKEN`. `--dry-run` never opens it.
    - `mint` skips keys whose `sha256` is already in `W/keys-used.json`, records
      the new `{run_id: sha256(key)}` entry atomically (`mkstemp` + `os.replace`)
      under a thread lock, and returns the next unused key. The file is read at
      construction, so a restart cannot hand out the same key twice. Exhaustion
      raises `KeyPoolExhausted` with the pool path and stops submitting new runs;
      runs already in flight finish.
    - `mint` ignores the per-arm budget/TTL arguments but rejects an arm whose
      `budget.usd` is above `--key-budget-usd` (default 2.0). The same check runs
      once before scheduling, so a bad matrix fails before any run starts.
    - `spend` waits 15 s (the gateway writes spend asynchronously), reads
      `info.spend` from `GET {gateway}/key/info` with the key as Bearer, then tries
      `GET {gateway}/spend/logs?api_key=…&summarize=false`. A non-200 logs
      response falls back to no per-request tokens, so the run document keeps the
      gateway spend and the agent-reported cost already stored by
      `build_run_document`. HTTP and `sleep` are injectable.
    - `revoke` is a no-op: the owner deletes the batch by alias prefix.
  - `--manifest PATH` (default `tasks/public-v1.manifest.json`) selects exactly
    the manifest's `task_id`s; any id missing from the store's valid tasks is an
    error. `--task` still filters within that set.
  - Scheduling now keeps at most `max_parallel` futures outstanding. When the
    pool is exhausted it stops submitting, waits for the in-flight runs, prints
    the error and exits 1 instead of turning the shortage into `error_infra`
    verdicts for runs that never started.
- `tests/run_matrix/**`
  - New `test_key_pool.py`: distinct hand-out, hash-only persistence, no reuse
    after a restart, 0644 refusal, clean exhaustion, budget refusal, spend
    parsing from fake `/key/info` and `/spend/logs`, logs fallback, and a full
    `run` through `--keys-file` that stops after two of three planned runs
    without leaking the key to stdout, stderr or `keys-used.json`.
  - New `test_manifest_tasks.py`: manifest ordering and de-duplication, exact
    selection, `--task` filtering within the manifest, failure for a task missing
    from the store, bad manifest shape, and a dry run that only plans manifest
    tasks.
  - Existing run helpers now pass a manifest fixture; no production behaviour
    change was needed for them.

## Verified

- `make check`: exit 0 — `732 passed, 10 xfailed in 99.26s`; ruff check, ruff
  format and all schema validations clean.
- Targeted `tests/run_matrix`: 39 passed.
- The key never appears in `W/keys-used.json`, stdout or stderr in the
  end-to-end pool test; only `sha256` digests do.
- `KeyPool` really reads the file mode (the 0644 test fails on the permission
  check, not on a missing-file path) and the a-restart test constructs a second
  pool over the same used file.
- Spend parsing is exercised through an injected HTTP function; no test opens a
  socket. The 15 s wait is asserted through an injected sleeper.

## Not verified

- No real LiteLLM `/key/info` or `/spend/logs` response: the field names and the
  `info.spend` shape are implemented from the spec, not checked against a live
  gateway.
- No real Harbor/Docker run and no real key batch: correctness of the owner-side
  minting (alias prefix, per-key budget/TTL) stays outside this repository.
- Concurrency of multiple runner processes sharing one `keys-used.json` is not
  covered; the lock is in-process (threads), as specified.

## Open questions / remaining out-of-scope items

1. **Spend/logs token fallback.** The runner document has no agent-reported
   token counts, only `agent_reported_usd`; when `/spend/logs` is unavailable the
   gateway token counters stay at zero, matching the previous behaviour.
2. **`/key/info` failure.** It currently fails the attempt (recorded as
   `error_infra`); there is no fallback spend source besides the key service the
   pool replaces.
3. **Default manifest in this checkout.** `tasks/public-v1.manifest.json` is not
   generated here (F0-17 data lives outside the repo); real runs must pass or
   have that file present.
