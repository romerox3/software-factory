# F0-18 — matrix runner report (fix 4)

## What changed

Trials no longer install executor CLIs from the network inside the sandbox, and
Harbor setup failures are recorded as `error_infra` instead of `reject`.

- `infra/harbor/factory_harbor_agents.py` (new)
  - `PinnedClaudeCode`, `PinnedCodex`, `PinnedOpenCode`, `PinnedMiniSweAgent`
    subclass Harbor's four installed agents.
  - Each overrides `install()`: it runs `claude --version`, `codex --version`,
    `opencode --version` or `mini-swe-agent --help`, parses the first `X.Y.Z`,
    and returns only when it equals `self._version`. Otherwise it raises
    `RuntimeError("<cli> <wanted> is not baked into the task image (found
    <got>); refusing to install over the network")`.
  - No call to the parent installer; the module imports only `harbor` and the
    standard library.
- `factory/adapters/config.py`
  - Every `harbor_agent` is now the import path
    `factory_harbor_agents:Pinned…`.
  - `MINI_SWE_AGENT_IMAGE` adds `--with litellm --with orjson --with fastapi`,
    the runtime extras Harbor's own mini-swe-agent install uses.
- `factory/run_matrix.py`
  - New `harbor_environment()` puts `<repo>/infra/harbor` first on the child
    `PYTHONPATH`, keeping any inherited value after it.
  - `_setup_failure()` detects a non-null `exception_info` with no
    `agent_execution` timing. Such an attempt gets an `error` run document and
    an `error_infra` verdict with `"<exception_type>: <message[:300]>"`
    (secret-redacted), skipping the verifier. Exceptions after the agent ran
    still go through `map_exit`.
- Tests
  - `tests/adapters/test_factory_harbor_agents.py`: an AST test (no Harbor
    needed) checks the module imports nothing from `factory`, defines the four
    classes with the right parents, and never calls `super().install`; a
    `pytest.importorskip("harbor")` test checks the subclassing when Harbor is
    installed.
  - `tests/adapters/test_harbor.py`: every `harbor_agent` is the import path,
    and the mini-swe-agent image carries the three extras with no
    `pip install`.
  - `tests/run_matrix/test_run_matrix.py` plus two fixture trials: the Harbor
    env starts with `infra/harbor`; a setup exception yields `error_infra`
    (verifier not called, retried as `a2`); an `AgentTimeoutError` after
    `agent_execution` keeps the old `budget_exceeded` mapping.

## Verified

- `make check`: exit 0 — `744 passed, 1 skipped, 10 xfailed in 92.62s`; ruff
  check, ruff format and all schema validations clean.
- The skipped test is the Harbor import/subclass test: `harbor` is not a
  dependency of this repository's environment, which is why the AST test exists.
- The pinned module's assumptions were checked against Harbor `v0.25.0`
  source: `BaseInstalledAgent.setup()` calls `install()`; `environment.exec()`
  returns `return_code`/`stdout`; `self._version` is the requested version;
  `--agent` accepts `module:Class`; OpenCode and MiniSweAgent install
  unconditionally, while ClaudeCode and Codex short-circuit on a matching
  version; Harbor's mini-swe-agent install uses the same three `--with`
  extras.
- `mini-swe-agent --help` for 2.4.6 emits `… version 2.4.6.`, so the shared
  `X.Y.Z` parser works for all four CLIs.

## Not verified

- No A3 rerun and no real task-image build: the network-less install path was
  not exercised against Harbor/Docker here.
- The Harbor-free environment cannot construct the real agents, so only the
  AST shape and the source-level assumptions above were checked; the
  `importorskip` test stays skipped until Harbor is installed.
- `mini-swe-agent --help` output was read from the 2.4.6 wheel source, not
  executed from the built task image.
