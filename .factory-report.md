# F0-18 — matrix runner report (fix 3)

## What changed

Executor CLIs now install into the task images without assuming Node.js and
without modifying the task's own Python environment.

- `factory/adapters/config.py`
  - New digest-pinned constants with comments: `NODE_IMAGE`
    (`node:22-bookworm-slim`) and `UV_IMAGE` (`ghcr.io/astral-sh/uv:0.9.5`).
  - `claude-code`, `codex` and `opencode`: the Node runtime is copied from
    `NODE_IMAGE` into `/opt/factory-node`; `PATH` is **appended**
    (`ENV PATH=$PATH:/opt/factory-node/bin`) so the task's tools keep
    precedence; the CLI is installed with
    `npm install --global --prefix /opt/factory-node <package>@<version>`.
  - `codex` keeps the `--version` wrapper that hides stderr (spike 01, B3);
    `command -v codex` now resolves to `/opt/factory-node/bin/codex`.
  - `mini-swe-agent`: `uv` is copied from `UV_IMAGE` into `/usr/local/bin`, and
    the package is installed with `uv tool install --python 3.12` into
    `/opt/factory-tools` (`UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`,
    `UV_PYTHON_INSTALL_DIR`). `PATH` is appended with
    `/opt/factory-tools/bin`. No `pip install` touches the task env.
  - `image_snippet(name)` still returns the ordered Dockerfile lines.
- `tests/adapters/test_harbor.py`
  - The snippet test now accepts a leading `COPY`/`ENV` and asserts that every
    executor's snippet has a `RUN`.
  - New parametrized test over all executors: no `pip install`; every
    `npm install --global` carries `--prefix /opt/factory-node`; every
    `ENV PATH=` appends (`=$PATH:`); every `COPY --from=` is pinned by
    `@sha256:`.
  - Existing version/package pin tests and the `to_harbor` placement test were
    kept and pass unchanged.

## Verified

- `make check`: exit 0 — `736 passed, 10 xfailed in 90.97s`; ruff check, ruff
  format and all schema validations clean.
- Both image references resolve:
  `docker buildx imagetools inspect node@sha256:4b150b48…` and
  `… ghcr.io/astral-sh/uv@sha256:f459f6f7…` return their manifests.
- Built the three snippets for real on `FROM debian:12-slim` (same base family
  as the task images, no Node, no Python): build exit 0. In the resulting
  container, without a login shell:
  - `opencode --version` → `1.19.5`
  - `codex --version` → `codex-cli 0.166.0` (stderr suppressed by the wrapper)
  - `mini-swe-agent --help` → help, exit 0
  - `node --version` → `v22.23.4`
  - `python3` is absent from the base image, so the task env was not used for
    the tool install.
- `PATH` ends with `/opt/factory-node/bin` and `/opt/factory-tools/bin`, after
  the system directories.

## Not verified

- No full SWE-rebench task image build and no A3 rerun: the actual task images
  and the hidden-test environment stay outside this repository.
- Harbor's command execution shell is not exercised. The snippet relies on the
  image `ENV PATH` (the same mechanism the repo already uses for the task env
  bin); a login shell that resets `PATH` would ignore it.
- The digest-to-tag mapping is taken from the fix instructions and confirmed to
  resolve; it was not independently cross-checked against upstream release
  pages.
