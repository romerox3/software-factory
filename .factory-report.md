# F0-18 — matrix runner report (fix 5)

## What changed

### 1. Model limits per arm

- `matrix/arms-v1.json`: every arm now carries
  `model_limits: {"context": int, "output": int}` — 200000/32768 for the
  `zai/glm-5.3` and `anthropic/claude-sonnet-5-5` arms, 32768/8192 for the
  `local/nanbeige4.3-33b` arms.
- `factory/adapters/harbor.py`: `build_harbor_command(..., model_limits=...)`.
  - OpenCode puts `models.<alias>.limit = {"context": C, "output": O}` inside
    `provider.openai`; the key is the alias OpenCode sees after the `openai/`
    prefix.
  - Codex adds `model_context_window` and `model_max_output_tokens` to the
    inline `config`.
  - Claude Code and mini-swe-agent are unchanged, and `None` produces the same
    argv as before.
- `factory/run_matrix.py`: `Arm` carries `model_limits`; validation requires a
  `model_limits` object with exactly `context` and `output`, both integers
  `>= 1`; `_harbor_command` passes them to the adapter.

### 2. Shadow vs real cost

- `matrix/arms-v1.json`: every arm declares `billing` (`"plan"` for all six:
  Anthropic subscription, z.ai coding plan and the local model).
- `factory/run_matrix.py`: `load_matrix` rejects a missing or unknown
  `billing`. `_gateway_usage(payload, billing)` moves the key spend to
  `usd_shadow` (leaving `usd_real` at 0) for `plan` arms and to `usd_real`
  (leaving `usd_shadow` at 0) for `api` arms. `load_dataset` still reports the
  sum, so the dataset cost is unchanged.

### 3. Tokens when the gateway has no per-request logs

- `factory/run_matrix.py`: when the spend payload has no `requests` list (the
  `/spend/logs` call did not return 200), `_agent_reported_tokens()` reuses
  `factory.normalize` for the executor and sums every `usage` event. The
  mini-swe-agent trajectory is serialized back to JSON so its normalizer can
  read it. Tokens are never left at zero when the agent reported them.
- `factory/adapters/output.py` and `schemas/executor-output.schema.json`:
  the token `source` now comes from the usage payload (default `gateway`), and
  the schema accepts `agent`.

**Deviation from the allowed-files list:** marking `tokens.source = "agent"`
cannot be done from the listed files alone — `output.py` hard-coded `gateway`
and the schema enum rejected `agent`. Those two minimal edits were made;
without them the field would either lie about the source or fail validation.
The schema keeps `trajectory` for compatibility.

### Tests

- `tests/adapters/test_harbor.py`: the OpenCode `models.<alias>.limit` block
  appears only with limits; Codex carries both window fields; default argv is
  byte-identical with `None`.
- `tests/run_matrix/test_run_matrix.py`: the shipped arms file loads with the
  expected limits and `plan` billing; missing/invalid `billing` and missing or
  malformed `model_limits` are rejected; a `plan` arm reports shadow only and
  an `api` arm real only.
- `tests/run_matrix/test_key_pool.py` + `fixtures/harbor_opencode/`: a
  `step_finish` stream with the spend-logs endpoint returning 401 yields the
  summed counts (`input` 150, `output` 15, `cache_read` 30, `cache_write` 3,
  `reasoning` 5) and `source: agent`.
- `tests/run_matrix/support.py`: the arm helper now emits `billing` and
  `model_limits` defaults.
