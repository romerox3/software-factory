# F0-18 — matrix runner report

## What changed

New files only; no existing module was modified.

- `factory/run_matrix.py` (new): matrix runner and gate.
  - `run --store S --arms matrix/arms-v1.json --out runs/ --work W [--arm A3 ...] [--task ID ...] [--k N] [--dry-run]`
  - `check runs/` (also accepts the roadmap form `--check runs/`).
  - Plan = valid store tasks × arms × `k`, with deterministic ids `<arm>-<task-id>-r<rep>-a<attempt>`; ids are lowercased/sanitized to the `^[a-z0-9][a-z0-9-]{7,63}$` rule (long task ids get an 8-char sha256 suffix).
  - Idempotent: a `(arm, task, repetition)` whose latest verdict is not `error_infra` is skipped; `error_infra` is retried as `a2`, `a3`, then stops (3 attempts max).
  - Per run: task converted once per task through `to_harbor` into `W/harbor/<task_id>`; executor-input document built and validated against `schemas/executor-input.schema.json`; key minted with the arm budget (`data_class` selects the team), TTL `wall_s + 600`; `build_harbor_command` argv run through the injectable `Deps.harbor` with env `os.environ | {name: value}`, timeout `wall_s + 600`; key always revoked in `finally`.
  - Outputs: `runs/runs/<run_id>.json` (schema-valid run document from `build_run_document`/`write_run_document`), `runs/runs/<run_id>.diff` (`diff.uri = runs/<run_id>.diff`), `runs/verdicts/<run_id>.json` (moved from the verifier output dir). This is the layout `factory/metrics/load.py::load_dataset` reads.
  - Diff comes from the Harbor trial's `verifier/diff.patch`; stats are parsed with `git apply --numstat -z`. `compute_diff` is not used: there is no exported workspace to diff.
  - Any exception inside one run still writes a schema-valid run document plus a schema-valid `error_infra` verdict, so every planned run has both files.
  - Concurrency: thread pool of `max_parallel` workers plus one semaphore per provider.
  - Secrets: key values never printed, logged or written; only env **names** appear. `--dry-run` prints planned ids and the Harbor argv only.
  - `check` groups verdicts by `(arm, task_id, repetition)`, keeps the latest attempt, and requires: every run has a schema-valid verdict, ≥ 95 % of cells have a schema-valid run document, and `error_infra` ≤ 5 % of cells. It prints the three numbers and exits non-zero otherwise.
- `matrix/arms-v1.json` (new): six arms A1–A6 exactly as the task table, per-run budget `usd 2.0`, `wall_s 1800`, `max_turns 60` for claude-code, provider limits `anthropic 3`, `zai 5`, `local 2`, global `max_parallel 3`. It is an object (`schema_version`, `max_parallel`, `providers`, `arms`) instead of a bare list, because the provider/global limits belong in the same file per the task.
- `tests/run_matrix/` (new): `support.py` (fake key client, harbor runner, verifier runner, clock, task store), `test_run_matrix.py` (20 tests), and the fixture `fixtures/harbor_trial/{result.json,agent/claude-code.txt,verifier/diff.patch}`.

Gateway alias handling: the executor's `model_prefix` is stripped only when the configured alias starts with it, so A1 stays `anthropic/claude-sonnet-5-5` and A2/A3/A6 become `openai/zai/glm-5.3` for a Codex harness that prefixes `openai/`.

## Open questions / out-of-scope blockers

1. **Real runs will have empty diffs.** `factory/tasks/to_harbor.py::_build_test_script` writes only `/logs/verifier/reward.txt`; nothing in production writes `verifier/diff.patch`. As specified, `run_matrix` reads that path, so a real job yields an empty patch and the verifier rejects it as `empty_diff` instead of `error_infra` — the gate would look "green" on a dataset of rejects. Fixing it means changing `factory/tasks/to_harbor.py` (emit a patch from the image before/after the agent), which is outside the allowed files, so it was not done.
2. **Executor CLIs are not in the image.** `to_harbor._build_dockerfile` only does `FROM` + checkout/snapshot + `ENV PATH`. Unless the base image already ships the executor, claude-code/codex/opencode/mini-swe-agent cannot start. Also outside the allowed files.
3. **Docs contradiction.** `docs/04-executor-contract.md` says the host computes the diff (`compute_diff`) and `docs/05-verification-design.md` describes pulling `diff.patch` from the generator; `.factory-fix.md` says read `verifier/diff.patch`. I followed the task. One of the two docs needs updating.
4. **Spend has no real/shadow split.** `/spend` returns a single `spend_usd` (`factory/gateway/service.py:143`). `run_matrix` maps `usd_real` (or `spend_usd`) into `usd_real` and leaves `usd_shadow` at 0. For the local aliases A4/A5 that overstates real spend. Deciding the convention (or splitting it in the gateway) is a change outside this task.
5. **Raw trial artifacts stay in `W/jobs/<run_id>/`.** The agent stream/trajectory is read in place for `map_exit` but not copied into `runs/`, and the run document does not reference it. Fine for the gate; if the work dir is ephemeral, the raw traces are lost.
6. **Retries leave older attempts on disk.** `check` ignores superseded attempts, but `load_dataset` will load every `runs/*.json`. If downstream metrics should count one row per cell, `factory/metrics/load.py` needs the same "latest attempt" rule; not changed here.
